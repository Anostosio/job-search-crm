# Job Search CRM — Security Notes

**Anostosio° / Product Lab**  
Baseline: **4 September 2026**

The product intentionally keeps user workspace data in the browser. Security controls should protect that local-first property rather than adding unnecessary infrastructure.

## Trust boundaries

The main untrusted inputs are:

- company and role;
- vacancy description and notes;
- recruiter/contact fields;
- vacancy URL;
- candidate profile text;
- imported JSON backups;
- data copied from external job postings by the user.

All imported or user-entered strings must be treated as data, never executable markup or code.

## DOM / XSS

The UI already HTML-escapes user-controlled strings used inside generated HTML.

Imported identifiers were additionally hardened because some IDs are used in `data-*` attributes. `lib/jobs.js` and `lib/profiles.js` now accept only a restricted identifier character set and replace unsafe imported IDs.

Activity history is normalized into a bounded structure before rendering so malformed imported history cannot provide arbitrary object shapes to UI code.

### Rule for future development

Prefer `textContent`, DOM properties and explicit element creation for new user-controlled content. If an existing template string must be used, every user-controlled value must be escaped or structurally constrained before interpolation.

## URL handling

Vacancy URLs are normalized by `sanitizeUrl()`:

- only `http:` and `https:` are allowed;
- embedded username/password credentials are rejected;
- missing/invalid hosts are rejected;
- URL length is bounded.

External links use `target="_blank"` together with `rel="noopener noreferrer"`.

Do not broaden the protocol allow-list without a security review.

## Import safety

JSON import is local and includes:

- maximum file size of 2 MB;
- maximum 5,000 vacancy records;
- maximum 50 candidate profiles;
- recognized-envelope validation;
- rejection of backups from a future unsupported schema version;
- rejection of dangerous object keys (`__proto__`, `prototype`, `constructor`);
- maximum nesting depth;
- plain-record checks for vacancy/profile entries;
- field and list normalization;
- safe ID normalization;
- safe URL normalization.

JSON is parsed with `JSON.parse()` and is never passed to `eval`, `Function` or a script loader.

## Export safety

JSON/CSV files are created locally through `Blob` and object URLs.

CSV cells beginning with spreadsheet formula markers (`=`, `+`, `-`, `@`) are prefixed with an apostrophe before quoting. This reduces formula-injection risk when a backup is opened in Excel, Google Sheets or similar software.

Download filenames are generated by the product and additionally restricted to a safe filename character set.

## Network surface

The strict local-first build removes:

- the `/api/parse-vacancy` Vercel Function;
- server-side vacancy fetching;
- Yandex Metrica;
- Google Analytics;
- Google Fonts runtime requests.

The emitted runtime build is checked for known removed external/privacy endpoints.

The Vercel Content Security Policy sets `connect-src 'self'`, which prevents browser JavaScript from making arbitrary cross-origin fetch/XHR/WebSocket connections unless the policy is deliberately changed.

## Fonts and dependencies

Fontsource packages are build-time dependencies only. The build copies the required Manrope and Unbounded WOFF2 subsets plus their OFL license files into the static output. `node_modules` is not part of the deployed application output.

Dependency versions are pinned in `package.json`. Review version changes before upgrading.

## Hosting

Vercel remains a technical hosting provider. Infrastructure request metadata and hosting logs are not the same as the CRM contents stored in browser localStorage.

Do not add application logging that records vacancy URLs, notes, recruiter contacts, imported backup contents or other workspace data.

## Future-function privacy/security gate

Before adding any of the following, perform a new data-flow, privacy and threat-model review:

- authentication/accounts;
- Supabase or other cloud storage;
- cloud sync/backup;
- server-side notifications;
- AI/LLM API calls;
- server-side vacancy parsing;
- collaboration/shared workspaces;
- email or calendar integrations;
- visitor analytics or session replay.

Any such feature changes the current security assumptions and must not silently reuse the existing privacy wording.
